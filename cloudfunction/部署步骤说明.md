# 后台用户信息同步 —— 云函数部署步骤（简化版 2026-10-08）

> 架构（已简化）：
> - **写**：用户端改资料后，经 RLS（`id = auth.uid()`，只能写自己那行）**直写** `yiwo_admin_profiles`，无需云函数。
> - **读**：管理后台 → 云函数 `admin-users`（凭 `ADMIN_SECRET`）→ 用 service_role API Key 读全表 → 返回 JSON。
> - 云函数只做"读"，零依赖（Node 20 内置 fetch），无需安装任何 npm 包。

---

## 第 1 步：建表（SQL 编辑器）

1. 控制台 → **SQL 数据库** → **SQL 编辑器**
2. 粘贴 `cloudfunction/建表.sql` 全部内容并执行
3. 确认：表 `yiwo_admin_profiles` 创建成功、3 条本人策略 + 2 条 GRANT 都执行成功

## 第 2 步：准备 3 个值

| 值 | 从哪来 |
|---|---|
| `ENV_ID` | `yiwoapp-d9g9zythq6a6cee08`（已知） |
| `CLOUDBASE_API_KEY` | 控制台 → **环境设置 / API 密钥** → **API Key（service_role，服务端用）**，创建或复制。⚠️ 不是前端在用的 Publishable Key |
| `ADMIN_SECRET` | 32 位随机串（部署时由 AI 生成提供；⚠️ 勿提交到公开仓库/前端代码） |

## 第 3 步：部署云函数（替换 hello world 的代码）

1. 控制台 → **云函数** → 函数列表 → 点开现有函数 `http-node-helloworld-9688`
2. **函数代码** 页 → 选择**上传 zip**（或"编辑代码"）→ 上传 `cloudfunction/admin-users.zip`
   （zip 根目录含 `index.js` + `package.json` + `scf_bootstrap`，监听 9000 端口，零依赖）
3. **函数配置** 页 → **环境变量** → 新增 3 条：
   - `ENV_ID` = `yiwoapp-d9g9zythq6a6cee08`
   - `CLOUDBASE_API_KEY` = （第 2 步复制的 API Key）
   - `ADMIN_SECRET` = （AI 生成提供的 32 位管理密钥）
4. 保存后重新部署，函数状态变「正常」

## 第 4 步：拿 HTTP 访问地址

1. 函数详情 → **访问服务 / HTTP 触发 / 接入函数**，开启 HTTP 访问
2. 复制生成的访问地址（形如 `https://xxx.service.tcloudbase.com/...`），**发给 AI**

## 第 5 步：配置管理后台

1. 打开后台 → **用户管理**，首次会弹"云端同步设置"：
   - 云函数地址 = 第 4 步的地址
   - 管理密钥 = （AI 生成提供的 32 位管理密钥）
2. 自测：浏览器直接开 `https://<函数地址>?secret=<你的ADMIN_SECRET>`
   - 返回 `[]` 或 JSON 数组 = 通了
   - 返回 403 = secret 错；500 config_missing = 环境变量没生效（检查后重新部署）

## 第 6 步：实测同步闭环

1. 用户端登录测试账号 → 修改资料（手机号/年龄/生日）→ 触发同步
2. 后台「用户管理」刷新 → 应看到该用户含私密字段的最新资料

---

## 安全红线

- `CLOUDBASE_API_KEY`（service_role）能绕过 RLS 读全量数据，**只能**放云函数环境变量。
- `ADMIN_SECRET` 只填在管理后台（存本机 localStorage），不下发到用户端。
- 用户端写入靠 RLS 兜底：`id = auth.uid()` 的三条策略保证任何人改不了别人的行。
